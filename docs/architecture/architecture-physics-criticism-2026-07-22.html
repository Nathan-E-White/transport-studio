Top recommendation: deepen the evidence spine first

Strong recommendation

Build one claim-aware Verification & Eligibility module before adding another solver name. It should own repository-set acceptance thresholds, normalized residuals, correction-debt gates, statistical qualification, resolved physics-data identity, estimator meaning, benchmark tiers, and the rule that failed preflight emits no physics result.

flowchart LR I["Compiled problem"] --> P["Eligibility\ndata · geometry · units · estimator"] P --> R["Run"] --> E["Evidence\nresiduals · uncertainty · provenance"] --> C["Claim decision"] C -->|qualified| U["Product result"] C -->|not qualified| D["Diagnostic only"]

Why this wins: it has the highest leverage across TypeScript, Rust, Monte Carlo, GRHD, M1, and the proposed hybrid method. It preserves the project’s good ADR discipline and turns it into executable discipline. It also makes later method work easier to judge: a new implementation either satisfies the same evidence or remains substrate.

First tracer bullet: one homogeneous photon slab with fixed exterior surfaces; resolved cross sections; absolute source normalization; track-length flux with uncertainty; analytic attenuation; an independent continuous Monte Carlo check; and a passive, frame-explicit GRHD coupling snapshot. No BSSN backreaction yet.
